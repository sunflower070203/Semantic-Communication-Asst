# 项目策划书：语义通信助手（Semantic Communication Assistant）

> 赛道一：Agent 应用开发（OpenTrek 平台）
> 团队成员：孙浩（东南大学）
> 最后更新：2026-08-23

## 1. 项目背景与问题

语义通信是 6G 与通信-人工智能深度融合的核心研究方向，近年论文数量快速增长（Deep JSCC、
DeepSC、任务导向通信、语义信息论等子方向）。对通信领域的研究生和科研新手，痛点集中在两点：

1. **找文献难**：方向分散、关键词多样，不知道从哪篇经典论文入手；
2. **读文献难**：论文里概念密集、互相引用，通用大模型问答不区分领域、不给出文献来源，
   难以判断回答依据是否可靠。

## 2. 项目目标

构建一个面向语义通信/泛 CS 领域的 **文献问答 Agent**，做到：

- 基于精选的领域知识库（10 篇核心论文）回答问题；
- 回答带文献来源与页码级引用，可溯源；
- 同时提供两种形态：**知识库问答工作流（B 路线，主推）** 与 **角色对话自主 Agent（A 路线）**；
- 开箱即用：分享链接即可体验，无需本地环境。

## 3. 目标用户与使用场景

| 用户 | 场景 |
|---|---|
| 通信方向研究生 | 快速搞清"Deep JSCC / DeepSC / 语义通信挑战"等概念，拿到出处 |
| 跨方向科研人员 | 从零进入语义通信领域，按主题渐进提问 |
| 评审/参观者 | 直接对话体验，观察检索-总结-引用全流程 |

## 4. 技术方案

### 4.1 总体架构（基于 OpenTrek 平台）

```
用户提问
  → 语义通信知识问答（工作流，B 路线）
      多轮改写 → 文档召回（知识库向量检索） → 召回结果处理
      → 结果总结（LLM） → 引用组合 → 最终回答（带来源）
  → 语义通信自主 Agent3（角色对话，A 路线，备选演示）
      角色定义 + ReAct 引擎，自主规划与总结
```

### 4.2 知识库

- 平台：OpenTrek 文档知识库（kbCode `ryekr4gqw2pn`）
- 内容：10 篇语义通信核心论文（arXiv 全文明文，pdf 解析后切 chunk + 向量化）
  - 奠基：DeepSC（2006.10685）、Deep JSCC（1809.01733）、Semantic Communications:
    Principles and Challenges（2201.01389）、A Theory of Semantic Communication（2212.01485）
  - 扩展：视频/文本语义通信（2312.05062、2206.02596）、SNR-自适应 JSCC（2102.00202）、
    带语义重要性的 JSCC（2302.02287）
  - 理论：语义通信数学理论（2401.13387、2401.14160）
- 上传链路（API 直传，已跑通）：STS 临时凭证 → minio 预签名 PUT → 注册解析

### 4.3 Agent 工作流（B 路线，已发布 ONLINE）

- 11 节点 10 边：开始 → 多轮改写 → 文档召回 → 召回结果处理 → 选择器 →
  （直接输出 | 总结参数 → 结果总结 → 引用组合 → 文本组合 → 内容输出）
- 关键设计：改写后的查询直接驱动文档召回，避免"术语库/问答库"等空转分支；
  召回结果带 file_code 与页码元数据，供引用溯源。

### 4.4 自主 Agent（A 路线，已发布 ONLINE）

- 角色对话型（AutoBotV2）+ processAgentEngine/ReAct，qwen3.6-plus
- 角色定义 Prompt + 约束条件 Prompt；分享链接即可运行
- 说明：平台工具执行沙箱当前故障（挂载成功、执行报 AGENT_TASK_DEFAULT_FAILED），
  因此 A 路线作为"自主规划与总结"演示，检索走 B 路线知识库。

## 6. 演示方案

演示问题集（均已在真实运行中验证）：

1. 什么是语义通信？它和传统通信有什么区别？
2. Deep JSCC 的核心思想是什么？它是如何工作的？
3. Deep JSCC 和 DeepSC 有什么区别？
4. 语义通信目前面临哪些主要挑战？
5. 什么是任务导向通信？和经典通信范式有什么不同？
6. SNR 自适应的深度联合信源信道编码是如何实现的？

演示流程：分享链接打开 → 依次提问 → 展示"检索 → 总结 → 带引用回答"的完整过程，
并展示引用对应的论文原文片段（知识库 chunk 元数据）。

## 7. 创新点与亮点

1. **领域化知识库**：不是通用知识问答，而是把语义通信方向 10 篇核心论文变成可检索、可引用的领域资产；
2. **引用可溯源**：回答中的每条引用都对应知识库 chunk 的 file_code 与页码，评审可点击核对原文；
3. **双引擎演示**：工作流（确定性强、适合知识问答）与自主 Agent（角色化、适合自由对话）互补；
4. **全流程 API 化**：知识库上传、Agent 运行均可脚本化批量执行，为后续扩方向（泛 CS）留好自动化通道。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台工具执行沙箱故障（联网搜索等） | A 路线无法实时检索外部文献 | 主推 B 路线知识库问答；A 路线仅演示自主规划与总结 |
| 脚本沙箱禁网 | 流程内无法直接调外部 API | 检索全部收敛到平台知识库节点 |
| 设计页二次访问白屏（平台 bug） | 改配置困难 | 配置完成后不再进入设计页；要改就新建 Agent |
| 论文解析失败 | 召回覆盖下降 | 已确认根因是源 PDF 损坏，重新下载后 API 补传成功；解析状态可轮询 |
