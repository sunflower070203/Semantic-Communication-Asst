## 2. Agent 定义

- 名称：语义通信文献调研助手（SemanticCom Research Assistant）
- 演示问题：语义通信近三年的研究进展
- 核心闭环：
  1. 用户提出研究方向/问题
  2. LLM 节点：解析意图，输出结构化检索词（keywords、year_from、max_results）
  3. 脚本代码节点：调用 arXiv API / OpenAlex API 检索真实文献
  4. 程序筛选：按年份、相关性去重排序，截断 top N
  5. 知识库检索：语义通信基础概念与关键文献（RAG）
  6. LLM 节点：生成带来源引用的调研简报
  7. 输出：结构化简报（概述 / 关键论文 / 方法趋势 / 局限 / 下一步问题）
- 不做清单：自动综述长文、引用格式全家桶、多语言支持、个人文献库完整 CRUD

## 3. Harness 职责划分

- 模型职责：自然语言理解、检索词拆分、摘要写作、解释
- 程序职责（脚本节点）：API 调用、参数校验、去重、排序、截断、超时、错误分类、状态变更
- 原则：能程序计算的绝不交给模型；模型输出必须过类型 + 白名单校验，不能直接成为可信事实
- 状态：平台短期记忆（对话）+ 记忆库（研究方向、已读论文清单、偏好）

## 4. 工具层

- 检索工具（脚本节点）：arXiv API（export.arxiv.org）、OpenAlex API
- 知识库检索：平台知识库（app-pc-kb）内置检索工具
- 工具护栏：超时、结果条数上限、URL 白名单、无数据不产结论

## 5. 失败路径与降级

- 脚本节点出网失败 → 降级为仅知识库检索，明确告知用户
- 检索无结果 → 提示换关键词/放宽年份，不编造论文
- API 超时 → 重试一次，仍失败则降级
- 模型输出非 JSON/非法字段 → 程序校验失败，重试一次或友好报错
- 输入越界（超长/非法字符）→ 拒绝并说明规则
- 提示注入 → 工具参数白名单校验，拒绝越权字段

## 7. 知识库方案

## 8. 专家 Skill 方案

- 优先：平台 skillmanage 创建"语义通信专家" skill（术语约束 + 评估维度 + 输出格式）
- 兜底：系统提示词包实现同样约束
- 不阻塞主流程：如平台能力不符或时间不足，可降级为提示词包

## 9. 测试与评测

- 确定性评测：固定检索关键词 + 固定输入，断言筛选/去重/排序结果（不碰模型、不碰网络）
- 对抗矩阵：越界输入、无结果、API 超时、异常结构、提示注入、新会话隔离
- 线上验收：新会话完整闭环 + 修改后重评估 + 一个安全拒绝
