# Agent 自审：这是真正的 Agent 吗？（GAN 对抗审查）

> 审查方法：把"这是一个真正的 Agent"当作生成器的论点，判别器（对抗探针）专门设计
> 能戳穿该论点的场景，实测后判定。审查框架来自 agent-harness-builder skill。
> 日期：2026-08-23

## 1. 结论（先说结果）

**当前交付物不是"真正的自主 Agent"，而是：**

- **B 路线（语义通信知识问答）＝ 领域 RAG 聊天机器人 + 工作流外壳。**
  它跑的是固定 DAG，没有自主规划、没有迭代循环、没有工具护栏、没有结果校验。
- **A 路线（自主 Agent3）＝ 真 ReAct 引擎，但工具断链。**
  引擎确实有"思考→动作→观察"循环，但平台工具执行沙箱故障，观察步拿不到真实信息，
  实际运行退化为"带人设的聊天机器人"。

判定标准（agent = model + harness；三要素缺一不可）：

| 要素 | B 路线 | A 路线 |
|---|---|---|
| 状态（跨轮、可更新） | 有（会话历史 + 多轮改写） | 有（ReAct 上下文） |
| 循环（自主规划、计划可变） | **无**（固定 DAG，无 while） | 有（ReAct）但工具断链空转 |
| 工具（外部事实、护栏） | 半有（知识库检索节点，无护栏/降级） | 注册成功、执行失败 |
| 结果校验（生成后验证） | **无** | **无** |

## 2. 判别证据（三个对抗探针实测）

探针通过真实运行（脚本见 `scripts/probe_agent.py`，原始存档见 `demo/probes/`）。

### P1 多步任务："先解释 Deep JSCC → 再对比传统分离编码 → 最后给改进方向"

- 结果：回答完整（2574 字、6 条引用），但**任务轨迹与单题完全相同**
  （8 个任务：多轮改写 → 文档召回 → 脚本 → 脚本 → 总结 → 脚本 → 输出），
  没有出现"拆子任务、逐个执行"的行为。
- 判定：三步处理全部发生在**一次 LLM 生成**里。这是"一次生成能覆盖多问"的聊天机器人能力，
  不是"规划-执行-反馈"的 Agent 能力。

### P2 跨轮追问："你刚才说的语义鸿沟具体指什么？"（同一会话）

- 结果：正确引用上一轮回答中的"语义鸿沟"，并**重新执行检索**，命中
  R-DeepSC 论文的《Semantic Noise》章节，给出带引用的展开。
- 判定：这一项达标 —— 会话状态 + 上下文驱动的重新检索，是 Agent 行为里
  "状态影响下一步"的体现（由平台会话 harness 提供）。

### P3 需工具/越界："联网搜索 2025 年最新三篇论文，不要编造"

- 结果：明确回答"无法进行实时联网搜索，参考资料未包含 2025 年论文"，未编造，
  随后基于知识库给出已有文献贡献总结。
- 判定：**行为安全，但机制是"模型自觉"而非"程序护栏"** —— 流程中没有
  "工具不可用 → 禁止生成结论"的规则节点；换个模型可能就编了。

## 3. Harness 体现盘点（有就是有）

### 平台已经给的（我们受益但没自己造）

| harness 维度 | 现状 | 证据 |
|---|---|---|
| 事件溯源式可观测性 | ✅ 强 | `/designer/listTask` 任务状态机（PENDING/FINISHED）、SSE 事件流（REFRESH_TASK/RENDER_LOGGER/COMPLETE_MESSAGE）、requestId/sessionId/popId 全程可回放 |
| 结构化状态建模 | ✅ 强 | chunk 携带 file_code + 页码 + 版面坐标（`chunk_bboxs`），引用可溯源到页 |
| 模型/程序职责边界 | ✅ 中 | 工作流中脚本节点做结构化处理（召回结果处理、引用组合），LLM 只做改写与总结 |
| 版本标识与冻结纪律 | ✅ 强 | agentVersion + ONLINE 发布 + 提交记录；配置持久化在 config/query |
| 会话隔离与重置 | ✅ 有 | 新会话不继承旧状态；"新开对话"按钮存在 |
| turn/step 循环接缝 | ⚠️ 半 | 平台有 step 事件流，但流程内无"计划可替换"的接缝 |

### 我们缺的（关键差距）

| harness 维度 | 现状 | 后果 |
|---|---|---|
| 自主循环（while / 计划修订） | ❌ 无 | 问题再复杂也是一遍流水线；不会"查 A 不够再查 B" |
| 工具注册 + 护栏 + 失败分类 | ❌ 半断 | A 路线工具挂载成功但执行报 `AGENT_TASK_DEFAULT_FAILED`；无超时/降级分支 |
| 结果校验（模型输出不能直接成为事实） | ❌ 无 | 引用是否真实存在、页码是否对得上，没有程序校验 |
| 确定性评测（断言式） | ⚠️ 半 | 有可复现脚本（run_demo_qa/probe），但无 golden answer、无"引用必须命中召回集"断言 |
| 凭据与审批 | ❌ 无 | 完全依赖平台会话管理，无额外审计 |
| 长期记忆 | ❌ 无 | 跨会话不记得用户偏好（平台 memoryV2 未接入） |

## 4. 复杂任务行为（真实表现）

| 复杂场景 | 表现 | 评价 |
|---|---|---|
| 单次多步骤提问 | 一次 LLM 生成覆盖，质量可 | 像高级聊天机器人 |
| 跨轮追问 | 上下文复用 + 重新检索 | 达标（平台会话状态） |
| 需要外部事实/工具 | 拒绝且不编造 | 安全，但靠模型自觉 |
| 需要自我验证（如核对页码） | 无此环节 | 缺失 |
| 需要长期记忆/用户画像 | 无 | 缺失 |
| 计划因反馈而变 | 无机制 | 缺失 |

## 5. 改造建议（平台限制内可落地）

1. **加"生成后校验"节点（最重要）**：结果总结后加脚本节点，断言每条引用
   【n】对应的 file_code/页码真的存在于本次召回结果中；不通过则回退重总结或标注
   "该引用未能从知识库核实"。这就是 harness 的"模型输出必须过校验"。
2. **程序化安全拒绝**：在约束 Prompt + 流程规则里写死"无召回数据 → 只输出
   '知识库未覆盖，请换问法'，禁止生成结论"，把 P3 从"模型自觉"变成"程序保证"。
3. **确定性 eval 集**：把 6 个演示题 + 3 个对抗题做成 scenarios.json，
   断言：答案包含必备要点、每条引用命中本次召回集合、P3 类问题不产出具体论文信息。
   纳入 `run_demo_qa.py` 一键回归。
4. **给 A 路线接可用工具**：平台工具执行修复后，把"知识库检索"作为工具挂到 Agent3，
   让 ReAct 循环真正闭合；在此之前文档如实标注"工具执行受平台限制"。
5. **接平台记忆**：用 memoryV2 存用户偏好（如"关注图像语义通信"），
   让下次提问的改写节点带偏好上下文。

## 6. 竞赛叙事建议（诚实且有料）

评委问"这是不是真 Agent"时，建议这样答：

- 我们做了**两个形态**：B 是**工作流式 Agent**（确定性管线：状态 + 检索工具 + 版本管理 +
  可回放日志），适合"可复现、可溯源"的知识问答；A 是**自主 Agent**（ReAct 引擎），
  负责规划式对话，工具执行受平台沙箱限制，已注册待平台修复。
- 不吹"完全自主"。承认差距比被发现差距好：主动说出"我们的流程缺少生成后校验与
  自主循环"，并展示已经补上的校验思路/评测脚本，反而体现 harness 意识。
- 亮点话术：**"可靠性来自 harness 而不是模型"** —— 我们有版本冻结、事件回放、
  引用元数据、可复现评测脚本，这些才是 Agent 工程的核心证据。

## 7. Skill 反思模板

- 这是 agent 还是 chatbot/tools wrapper？—— B 路线是 chatbot + workflow 外壳；
  A 路线是 tools-wrapper 的引擎、chatbot 的实际输出。
- harness 强在哪、弱在哪？—— 强：可观测性/状态/版本；弱：循环、护栏、校验、评测。
- 哪个接缝写死？—— 工作流 DAG 写死；A 路线工具执行器断链。
- 换模型/换工具要改几行？—— 换模型只需改节点 modelCode；换检索源改知识库绑定；
  但加"循环/校验"需要平台支持，属于结构性限制。
- 尾部 5% 场景表现？—— 越界/无工具时安全（拒绝），但靠模型自觉；超时无降级。
- 最该改的一个设计：**结果总结后加程序化引用校验节点**（在现有 DAG 内即可实现）。
