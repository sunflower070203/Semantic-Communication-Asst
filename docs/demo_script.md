# Demo 演示脚本（口语版）

用途：录屏视频（4-5 分钟）与现场路演共用。线上链接为主，视频为录屏版。
语速按 150-180 字/分钟，全文约 800 字，正常读约 5 分钟。

## 演示前准备（一次做完，现场不再等）

1. 打开分享链接 `randomCode=297d4be1aa2443cca29b62b5be702beb`。
2. 依次跑完 6 个演示问题，让回答留在会话里。
3. 录制时打开同一会话，滚动展示已有回答，最后当场问一个新问题。

## 脚本

（开场，切屏幕到对话界面）

大家好，这是我们参加东南大学 AI+ 大赛赛道一的项目，语义通信助手。

一句话，它是帮你读论文的。你问它语义通信是什么，它不光回答，还告诉你这话是哪篇论文、哪一页说的。

（滚动已有回答，停在第一题）

先看第一个问题，什么是语义通信，它和传统通信有什么区别。回答分成几块，先讲定义，再讲区别。每条关键陈述后面都有引用标记，比如这个罗马数字一。页面下面跟着引用列表，注明出自哪篇论文的哪一部分。

（切到第三题，Deep JSCC 和 DeepSC 的区别）

第二个想给你看的，是引用校验。这是这个项目最核心的地方。

模型有时候会编引用。我们的做法不是靠它自觉，而是写了个程序来查。回答生成以后，系统做三方核对，正文里的引用标记、引用列表、还有实际检索到的内容，三边对一遍。对不上的，直接打一行警告，写清楚是哪条引用没能核实。

（切到架构图问题）

第三个亮点，画图。你让它画语义通信的系统架构，它会输出一段 mermaid 代码，聊天界面直接把它渲染成流程图。

这里有个背景。平台本身没有生图模型，我们也不打算硬造。用文本渲染把图画出来，一样能看图，而且图是矢量图，放大不糊。

（切到联网问题）

第四个想说的，是它知道自己不会什么。

你让它联网搜 2025 年的新论文，它会直接说，我连不了网，手头这些资料里没有 2025 年的内容，你可以去 IEEE 或者 arXiv 自己查。它不编。

（切到 GitHub 仓库或评测报告）

最后是工程部分。整个项目跑在东南大学指定的 OpenTrek 平台上，十篇语义通信核心论文做了知识库，全部解析成功。四个场景的自动化评测全绿，引用校验有六个单元测试，负路径也测了。

代码、文档、评测报告都在 GitHub 上，策划书和技术报告也一并提交了。

（收尾，切回对话界面）

就这样，谢谢。

## 现场路演备选（视频可选项时）

如果只交链接不交视频，现场演示用同一套内容，压缩到三分钟：

1. 打开链接，滚动已有回答，讲引用校验。
2. 当场问一个新问题，讲 mermaid 和拒绝行为。
3. 收尾讲工程与评测，指 GitHub。

重点永远放在引用校验。那是评分表创新性 30% 里最能证明 RAG 深度的一环。
