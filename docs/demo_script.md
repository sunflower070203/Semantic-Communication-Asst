# Demo 分镜表（录屏版）

用途：录屏视频（约 4.5 分钟）与现场路演共用。线上链接为主，视频为录屏版，后期配音。
方法论：借鉴 video-shotcraft 镜头配方卡——每个镜头写清楚用途、节奏、时长、画面操作、台词、已知坑，录制时照着做，不临场想。

## 0. 视频元信息

| 项目 | 设定 |
|---|---|
| 目标时长 | 4 分 30 秒（3.5-5 分钟均可接受） |
| 分辨率 | 1920×1080，录屏工具选 1080p |
| 台词总量 | 约 800 字，后期配音 150-180 字/分钟 |
| 镜头数 | 8 个正式镜头 + 1 个可剪掉的备用镜头 |
| 音频 | 只录画面不录音；配音单独录，每镜头一段 |
| 剪辑 | 剪映（国产免费），按镜头号对轨 |

## 1. 制作流程（五步，全程约 2 小时）

1. **准备（30 分钟）**：刷新浏览器登录态 → 跑 `scripts/prepopulate_share.py` 预填 4 个问答 → 打开分享链接逐题检查回答、确认引用校验警告可见 → 预热 GitHub 仓库标签页。
2. **录制（15 分钟）**：按第 2 节分镜表逐镜头录。每个镜头独立成段，录完一段马上看回放，不行就重录该段，不连累其他镜头。
3. **配音（20 分钟）**：按镜头逐段配音。每段配错只重录该段，全部配完再整体听一遍。
4. **剪辑（30 分钟）**：剪映里按镜头号排时间线，镜头间加 0.3-0.5 秒淡入淡出，配音对轨，加字幕。
5. **质检（10 分钟）**：按第 4 节清单逐项过一遍。

## 2. 分镜表

镜头卡字段说明：能量 = 节奏定位（定场/平推/高亮/收束），决定剪辑时给这个镜头留多少静止展示时间；台词 = 配音稿，录制时不念；字幕 = 后期画面叠加的关键词。

### S01 开场（0:00-0:12）

- 能量：定场，画面静止 2 秒再开始动
- 用途：一句话让评委知道这是什么、解决什么问题
- 画面：打开分享链接的对话界面，顶部停留，不要滚动
- 台词：大家好，这是我们参加东南大学 AI+ 大赛赛道一的项目，语义通信助手。一句话，它是帮你读论文的。你问它语义通信是什么，它不光回答，还告诉你这话是哪篇论文、哪一页说的。
- 字幕：语义通信助手 · AI+ 大赛赛道一
- 录制要点：开场前先深呼吸，前 2 秒保持画面不动，方便剪辑时压黑场
- 已知坑：链接加载慢时首屏是空白，等页面完全出来再录；不要录到浏览器地址栏的书签或账号信息

### S02 第一题·定义与引用（0:12-0:55）

- 能量：平推，滚动速度放慢，每停一处给 2 秒
- 用途：证明回答有结构、引用可溯源（定义 + 区别 + 引用标记 + 引用列表）
- 画面：缓慢滚动到第一个问题「什么是语义通信？它和传统通信有什么区别？」，停在回答正文，指出罗马数字引用标记；再缓缓滚到页面下方的引用列表
- 台词：先看第一个问题，什么是语义通信，它和传统通信有什么区别。回答分成几块，先讲定义，再讲区别。每条关键陈述后面都有引用标记，比如这个罗马数字一。页面下面跟着引用列表，注明出自哪篇论文的哪一部分。
- 字幕：结构化回答 · 引用标记 [I] · 引用列表
- 录制要点：鼠标光标移到引用标记处停住 2 秒再移开，后期配音说到「罗马数字一」时画面正好指在那里
- 已知坑：滚动太快会糊；引用标记字号小，录制前先用浏览器缩放（Ctrl + 加号）确认从 1080p 画面里能看清

### S03 第二题·引用校验（0:55-1:45）★核心亮点

- 能量：高亮，全片最重要的镜头，讲到引用列表时画面停 3-4 秒
- 用途：证明防编造不是靠提示词自觉，而是程序化三方校验；本回答引用全部通过，可逐条追溯
- 画面：滚动到第二个问题「Deep JSCC 和 DeepSC 有什么区别？」，指出回答正文的引用标记【I】-【IV】，再缓缓滚到下方的引用列表，逐条展示出处
- 台词：第二个想给你看的，是引用校验。这是这个项目最核心的地方。模型有时候会编引用。我们的做法不是靠它自觉，而是写了个程序来查。回答生成以后，系统做三方核对，正文里的引用标记、引用列表、还有实际检索到的内容，三边对一遍。这一整段回答里的每一处引用，都通过了校验，出处可以逐条追溯。
- 字幕：引用校验 · 三方核对 · 本回答引用全部通过
- 录制要点：先滚到回答正文指出引用标记，再滚到引用列表展示出处；两处各停 3-4 秒
- 已知坑：如果某处引用未能通过校验，回答里会出现警告行，那是更理想的画面；但不要为了凑警告去编造问题，全部通过同样有力

### S04 第三题·架构图（1:45-2:25）

- 能量：中，图渲染完成后静止展示 3 秒
- 用途：证明能输出图表，且用文本渲染绕开平台没有生图模型的限制
- 画面：滚动到第三个问题「画出语义通信系统的架构流程图」，等 mermaid 渲染完成（页面出现 SVG 流程图），从图顶部缓缓滚到图底部
- 台词：第三个亮点，画图。你让它画语义通信的系统架构，它会输出一段 mermaid 代码，聊天界面直接把它渲染成流程图。这里有个背景。平台本身没有生图模型，我们也不打算硬造。用文本渲染把图画出来，一样能看图，而且图是矢量图，放大不糊。
- 字幕：Mermaid → 流程图 · 矢量渲染
- 录制要点：mermaid 渲染要几秒，等图完全画出来再滚动；若图较长，先滚到图顶部开始
- 已知坑：渲染过程中画面跳动，等稳定后再动鼠标；录制前已确认分享页能渲染出 SVG 流程图（实测存在 836px 宽的可见图）；不要在这段提到"生图"时切到别的页面

### S05 第四题·诚实拒绝（2:25-3:05）

- 能量：中，拒绝理由让它在画面上完整出现
- 用途：证明模型有自知边界，不编造，比"硬答"更可信
- 画面：滚动到第四个问题「联网搜索 2025 年最新论文」，指出回答中"无法联网、没有 2025 年内容、请去 IEEE 或 arXiv 自查"的句子
- 台词：第四个想说的，是它知道自己不会什么。你让它联网搜 2025 年的新论文，它会直接说，我连不了网，手头这些资料里没有 2025 年的内容，你可以去 IEEE 或者 arXiv 自己查。它不编。
- 字幕：能力边界 · 明确拒绝 · 不编造
- 录制要点：确认"无法联网"和"IEEE / arXiv"字样都在同一屏可见，必要时先滚动到最佳位置再开始录
- 已知坑：回答较长时拒绝理由可能在折叠区，需要展开；录前检查有没有被折叠

### S06 工程与评测（3:05-3:55）

- 能量：平推，信息密度高，切页后先停 1 秒
- 用途：证明不是玩具 demo，有知识库、评测、工程交付
- 画面：切到预热好的 GitHub 仓库标签页（semantic-communication-asst），从上到下展示 README：项目名、徽章、架构说明、评测表；画面允许时切到评测报告截图
- 台词：最后是工程部分。整个项目跑在东南大学指定的 OpenTrek 平台上，十篇语义通信核心论文做了知识库，全部解析成功。四个场景的自动化评测全绿，引用校验有六个单元测试，负路径也测了。代码、文档、评测报告都在 GitHub 上，策划书和技术报告也一并提交了。
- 字幕：10/10 论文解析 · 4 场景评测全绿 · 6 个单元测试
- 录制要点：GitHub 页提前打开并刷新，避免录屏时现等加载；展示顺序从上往下一次滚完
- 已知坑：GitHub 仓库页可能因为网络慢白屏，录前先确认能打开；不要滚太快让 README 文字糊掉；注意别录到浏览器其他标签页

### S07 现场新问题（3:55-4:15）★备用镜头，可剪

- 能量：高亮收尾，回答出现前留白
- 用途：证明回答是实时生成的，不是背好的
- 画面：切回对话界面，输入一个新问题「语义通信在 6G 里有哪些典型应用场景？」，发送，等回答生成
- 台词：我们现场再问一个没准备过的问题，证明它是实时回答，不是背稿。（回答出来后）可以看到，它直接基于知识库里的论文给出了答案。
- 字幕：实时回答
- 录制要点：新问题选知识库能答的（不要联网题、不要太冷门）；回答可能要 30 秒到 2 分钟，等待段后期剪掉或快进
- 已知坑：回答失败或超时不要慌，停录、换备用问题（如"语义通信和传统通信在编码层面有什么不同"）重录这一段；备用问题也要提前试跑一遍

### S08 收尾（4:15-4:25）

- 能量：收束，画面静止 2 秒
- 用途：干净结束
- 画面：回到对话界面任意位置，静止
- 台词：就这样，谢谢。
- 字幕：无（或项目名淡出）
- 录制要点：说完后保持画面 2 秒再停录，给剪辑留余量
- 已知坑：停录太急，最后一句配音没地方放

## 3. 后期清单（剪映）

1. 按镜头号把素材拖进时间线，镜头间加 0.3-0.5 秒叠化或淡入淡出。
2. 配音逐段对轨：台词说到「罗马数字一」「警告行」时，画面必须正好停在对应位置；差 0.5 秒以上就微调视频或音频。
3. 字幕按台词逐句加，关键术语（引用校验、Mermaid、三方核对）可用与主题色一致的高亮。
4. BGM 可选：音量压到配音之下（建议 -18dB 左右），只做底噪填充，不要抢戏。
5. S07 的等待段剪掉或 4-8 倍速快进，加一个"正在生成"的字幕遮罩更自然。

## 4. 质检清单（录完、剪完各过一遍）

- 画面：1080p 不糊；滚动稳定不跳帧；没有录到通知弹窗、输入法候选框、浏览器书签、个人账号信息
- 引用：S02 的引用标记和引用列表清晰可见；S03 的校验警告行是画面主体
- 声音：配音与画面同步，无爆音、无环境噪音，BGM 不盖过人声
- 字幕：无错别字，术语统一（引用校验 / 三方核对 / Mermaid）
- 时长：4-5 分钟；超过 5 分钟优先压缩 S06 工程段
- 出口检查：视频文件命名规范（如 `semantic-comms-demo.mp4`），体积控制在 200MB 内，提交前能直接打开播放

## 5. 现场路演备选（视频可选项时）

如果只交链接不交视频，现场演示用同一套内容，压缩到三分钟：

1. 打开链接，滚动已有回答，讲引用校验（S03 的内容）。
2. 当场问一个新问题，讲 mermaid（S04）和拒绝行为（S05）。
3. 收尾讲工程与评测（S06），指 GitHub。

重点永远放在引用校验。那是评分表创新性 30% 里最能证明 RAG 深度的一环。
